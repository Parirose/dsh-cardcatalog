# dsh-cardcatalog v0.6.0

新增 `decay`：把“这条事实该不该淡出”“这份账本是不是太胖了”从人的自觉变成确定性计算。
每条事实算一个清晰度（vivid / clear / fuzzy / trace），每个源算一个体量百分比。
**只算、只显示、偶尔提示一行；不写任何文件。**

## 1. 为什么

现状有两个硬伤：

1. `facts.json` 只有 `ttlDays` 二元判定（过期 / 没过期）。过期了仍原样摆在账本里，
   没有“慢慢模糊”的中间态；而遗忘本来就是渐进的。
2. 近况文件没有体量红线，只增不减。等它涨到读不动，“接手时读近况”这条就形同虚设。

参考做法（都读过了）：

- `Mieksido/surfcore` 的衰减记忆卡：四档清晰度、被再次提到会回升、重要度打分是
  **纯函数不调模型**、模糊化是**确定性截断**而非模型摘要。
- `mashanglinyu/luanyujia-workbench` 的记忆机制：体量红线、到线动作、写回判据。

本版只取“算”的部分。搬运属于 v0.7，见 §12。

## 2. 三条不能破的原则

1. **零写入。** 不新建状态文件、不改 `facts.json`、不碰任何 markdown。
   `ci/check-readonly.mjs` 仍然 0 命中。清晰度是算出来的，不是存下来的。
2. **确定性。** 同一份账本 + 同一个时间点 ⇒ 同一个结果。不调模型、不随机。
3. **软硬分开。** `ttlDays` 继续表示“这条该重新验证了”（硬信号，标 stale）；
   clarity 表示“我还记得多清楚”（软刻度）。两者并存，互不替代。

## 3. 配置

### 3.1 `decay`

```yaml
decay:
  enabled: true
  graceDays: 14
  stepDays: 21
  recoverDays: 30
  maxRecover: 2
  importanceByScope:
    self: 90
    project: 70
    machine: 55
    tool: 45
    default: 50
```

- **只有 `decay` 这个对象标 `.extra('volatile', true)`**；`enabled` / `graceDays` /
  `stepDays` / `recoverDays` / `maxRecover` 一律不标。
- `importanceByScope` 是 dict：**dict 本身和子键都不标 volatile**。
- `DEFAULTS`、`CONFIG_KEYS`、`isBuiltInDefault()` 三处已同步；漏一处会出现
  “面板保存了但没生效”。

### 3.2 每个 source

```yaml
sources:
  - id: notes
    kind: markdown
    path: ~/.dsh/notes/notes.md
    sections: [称呼与偏好]
    maxBytes: 4096
    warnPct: 80
```

- `maxBytes`：体量红线（字节）；`0` = 不检查。
- `warnPct`：达到红线的这个百分比就算 `warn`；默认 80。
- 两者放在 `sources[]` 里，和 `maxChars` / `maxLines` 同层；list 子项不标 volatile。
- `DEFAULT_SOURCE`（挂在 `DEFAULTS.source`）、`normalizeSource()`、面板模板三处已同步。

## 4. 纯函数

### 4.1 `clarityOf(fact, config, hits, now)`

```js
{
  level, clarity, ageDays, importance, maxLevel, reason
}
```

- `importance = fact.importance ?? importanceByScope[fact.scope] ?? importanceByScope.default`
- `lastSeen = max(fact.verifiedAt, 最近一次命中时间)`
- `ageDays = (now - lastSeen) / 86400000`
- `steps = ageDays < graceDays ? 0 : min(3, 1 + floor((ageDays - graceDays) / stepDays))`
- `recover = min(maxRecover, recoverDays 窗口内的命中数)`
- `maxLevel = importance >= 80 ? 1 : importance >= 50 ? 2 : 3`
- `level = clamp(steps - recover, 0, maxLevel)`
- `clarity = ['vivid', 'clear', 'fuzzy', 'trace'][level]`

规则：

- `verifiedAt` 缺失或解析不了 ⇒ `level = 0`、`reason = 'no-date'`，不猜日期。
- `pinned: true` ⇒ `level = 0` 恒定，`reason = 'pinned'`。
- facts / jsonl 条目如果自带 `hits` 数组，会用它算复习；没有就只按 `verifiedAt`。

### 4.2 `redlineOf(config, statOf)`

```
pct   = maxBytes > 0 ? round(bytes / maxBytes * 100) : null
state = maxBytes === 0 ? 'off' : pct >= 100 ? 'over' : pct >= warnPct ? 'warn' : 'ok'
```

`maxBytes: 0` 时仍然报告实际 `bytes`，只是不判断。

### 4.3 `renderDecayLine(report)`

只在有跨档或有源 `warn` / `over` 时返回内容，否则空串。

## 5. 注入

- 接缝与目录 / nudge / tone / wall 同一个 `agent/pre-step`，`payload.step === 1`，非子代理。
- **两个条件都必须满足**：
  1. 距上次提示已跨天（`dayKey` 不同）；
  2. 本次至少 1 条事实降档，或至少 1 个源 `warn` / `over`。
- 去重：`state.decayReportedDay: Map<sessionId, dayKey>`，同一会话同一天最多一条。
  进程重启会重置，一天最多多报一两次；不写状态文件。
- 文本（`source.kind = 'cardcatalog-decay'`）：

```text
<memory-decay do-not-execute>
记忆保养：now.md 3182 B（78%，红线 4096）；3 条事实降档（2→模糊，1→印象）。
要搬的话搬到 notes/archive/（本版不会自动搬）。
</memory-decay do-not-execute>
```

- 没有跨档也没有过线 ⇒ **一个字都不注入**，只记日志。

## 6. 面板

`statePayload()` 增加：

- `decay.facts`：`{ vivid, clear, fuzzy, trace }`
- `decay.droppedToday`：最近一次提示里跨档的条数（没有则 0）
- `redline`：每个源 `{ id, bytes, pct, maxBytes, state }`

面板新增「记忆保养」卡：

- 四档分布：`鲜明 12 · 清楚 3 · 模糊 1 · 印象 0`
- 每个源一条容量条：绿（ok）/ 黄（warn）/ 红（over）；`maxBytes: 0` 显示“未设红线”
- 可编辑 `graceDays` / `stepDays` / `recoverDays` / `maxRecover`
- 文案里不出现用户名、项目名、绝对路径

## 7. 日志

- `decay：vivid 12 / clear 3 / fuzzy 1 / trace 0`
- `redline：now.md 3182 B（78%），未过线`
- `redline：now.md 4400 B（107%），过线`
- 接近红线时：`redline：now.md 3300 B（81%），接近红线`

每会话一次。

## 8. 测试

新增 `test/v060.test.mjs`，8 个用例：

1. grace 内 ⇒ `vivid`。
2. 过 grace ⇒ 1 档；再过 `stepDays` ⇒ 2 档；封顶 3 档。
3. `importance >= 80` ⇒ 最差停在 `clear`。
4. 低重要度且足够老 ⇒ `trace`。
5. `recoverDays` 内命中回升，且不超过 `maxRecover`。
6. `verifiedAt` 缺失 ⇒ `vivid` + `no-date`；`pinned` ⇒ `vivid`。
7. 红线 `off` / `warn` / `over` 三态。
8. `renderDecayLine` 空串 / 含条数与百分比；pre-step 注入一次、同日不重复。

`makeCtx` 给 `dshHomePath` 了 stub；不碰真实会话/真实 home。

## 10. 代价

每次 `agent/pre-step` 会重新读一次 facts/jsonl、stat 一次源文件；不建缓存、不写状态文件。
事实很多时会有少量只读 IO，这是“确定性计算、不存副本”的代价。

## 11. 本版不做

- **不写任何文件**（不建状态文件、不改 `facts.json`、不搬 `now.md`）。
- 不调模型做判断或摘要。
- 不改目录 / nudge / tone / wall 的现有行为和文本。
- 不做跨会话统计、不做历史曲线。

## 12. v0.7.0 预留

归档改写：超红线的源，把最旧的行搬进 `notes/archive/<name>-YYYY-MM.md`。

硬流程：先快照 → 先写归档 → **逐行核对**（搬前非归档行 == 搬后原件剩余 + 归档新增）→
通过才原子替换原件 → 尾部留一行指针。默认关，且只对配置里标了 `allowRewrite: true`
的源生效。

`ci/check-readonly.mjs` 届时改成“只允许 upkeep 模块使用 rename / appendFile”，
其他文件出现照样红。

本版把 `maxBytes` / `warnPct` 先落地，就是为了 v0.7 上来就能用同一套判定，
不用再改一次配置。
