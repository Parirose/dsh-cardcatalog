# dsh-cardcatalog v0.3.0

本版只把 nudge 的触发语义写明、显示在面板上，并锁进回归测试。**不新增任何写文件能力。**

## 1. 实测依据

探针条件：`fixtures/nudge/now.md` 的 mtime 拨到 4 小时前，模拟 9 轮 `agent/pre-step`
（`payload.step === 1`），记录每轮注入的消息里 `source.kind === 'cardcatalog-nudge'` 的那些行。

| 情形 | staleAfterHours | alsoEveryNTurns | 实际触发轮次 |
|---|---|---|---|
| A | 3 | 3 | 1、4、7 |
| B | 6 | 3 | 无 |
| C | 3 | 0 | 1 |

结论：默认值对应情形 C —— 一个持续进行的会话里最多只在第 1 轮检查一次，
宿主侧若期望「每隔几轮看一眼」，必须显式把 `alsoEveryNTurns` 设成 >0。

这张表的复现方式与 `test/v030.test.mjs` 的三条用例一致。

## 2. 改动

- `staleAfterHours` / `alsoEveryNTurns` 的 schema 描述改为明确的触发关系：
  `alsoEveryNTurns` 只决定检查频率，是否真提醒仍由 `staleAfterHours` 判定。
- 面板把 `alsoEveryNTurns` 标成「每 N 轮再检查一次」，并补一行说明两个数的关系。
- 面板新增只读状态：
  - `nudgeWillFire`：当前配置和文件状态下，下一次检查会不会真的提醒；
  - `nudgeHours`：近况文件距今多少小时。
- 新增 `test/v030.test.mjs`，把 A/B/C 三行固化成三条回归用例。

## 3. 不做

- 不新增写文件能力：不 append 任何账本、不创建近况文件、不改用户的 markdown。
- 不新增配置字段，复用现有两个数。
- 不改 `buildNudge()` 的判定顺序（`if (!info.stale) return null` 保持原样）。
- 不动 `agent/pre-step` 里目录与 nudge 的合并逻辑。

## 4. 验收

- `npm test`：45 + 3 条（含 `test/v030.test.mjs`）。
- `npm run check:privacy`：0 命中。
- `npm run check:readonly`：0 命中。
- `node --check index.js`、`node --check client.js`：0。
