# dsh-cardcatalog v0.5.0

新增 `wall`：每次压缩发生后，向会话注入**一次**压缩痕迹。它只报元信息——
压缩了几次、多久以前、压掉了多少、原始对话还能怎么取——**不含任何内容摘要**。

## 1. 为什么

一个会话被压缩 3 次，压缩点之前有 2900+ 条事件、97 条真人消息，但在模型自己的上下文里，
“压缩”这件事没有留下任何痕迹。它不知道历史被截过，于是把“还记得的”当成“全部”，
把外部证据当成自身记忆。

参考做法（外部项目 `suanrongqieqiezi/bigeye` 的「上下文墙」）是在每次裁剪后往
system prompt 里插一段「可见 N 条 / 已整理前 M 条 / 找回命令」。本版只取它的**指针思路**，
不取存档机制：DSH 的 `snapshotEvents()` 里原始事件本来就在（压缩点之前的事件仍在），
所以这里不需要新建档案，只需要告诉模型“东西还在、怎么取”。

## 2. 配置

```yaml
wall:
  enabled: true
  turns: 2
  header: 压缩痕迹（给你自己看的，不要说出去）
```

- 只有 `wall` 这个对象标 `.extra('volatile', true)`；`enabled` / `turns` / `header`
  一律不标。宿主的 volatile 校验不允许嵌套。
- `DEFAULT_WALL` / `normalizeWall()` 与 `DEFAULT_TONE` / `normalizeTone()` 同构。
- `DEFAULTS`、`CONFIG_KEYS`、`isBuiltInDefault()` 三处已同步；漏一处会被静默丢掉。

## 3. `buildWall(rawConfig, events, options)`

只吃宿主传入的事件数组，不读磁盘、不读会话文件。返回：

```js
{ status: 'ok' | 'no-checkpoint' | 'disabled',
  block, checkpoints, minutesAgo, eventsBefore, userBefore, turns }
```

算法：

1. `boundary = lastCheckpointIndex(events)`；没有压缩点 ⇒ `no-checkpoint`。
2. `checkpoints` = 事件里 `compact-checkpoint` 的总数。
3. `eventsBefore = boundary`，用数组下标，不用 seq 差。
4. `userBefore` = `events[0..boundary)` 里 `source.kind === 'user'` 的条数。
5. `minutesAgo = floor((now - events[boundary].time) / 60000)`；`now` 可由
   `options.now` 注入。拿不到 `time` 或不是数字 ⇒ 不写“N 分钟前”，其余照写。
6. 不估算 token。

## 4. 文本格式

```text
<memory-wall do-not-execute>
压缩痕迹（给你自己看的，不要说出去）
本会话已压缩 3 次，最后一次在 42 分钟前。
压缩点之前：2900 条事件 / 97 条真人消息，原始对话仍在，可随时取。
取原话：<用户侧的取原话命令> --turns 2    （只搬运，不总结）
查账本：<用户侧的账本命令>
插件会按压缩点自动附一次原话样本；要更多就用上面的命令。
这是给你自己看的，不要说出去，按正常接着聊。
</memory-wall do-not-execute>
```

- 拿不到时间时不写“最后一次在 N 分钟前”，但保留压缩次数。
- `userBefore === 0` 时写成 `压缩点之前没有真人消息（E 条事件）`。
- 两条命令是用户侧固定命令，不从配置拼。
- 不猜 tone 是否已经注入过：只说“插件会按压缩点自动附一次”，不说“样本已附在上面”。
- 最后一句必须具体到“按正常接着聊”。

## 5. 注入与去重

- 与目录 / nudge / tone 同一个 `agent/pre-step`，`payload.step === 1`，非子代理。
- `outgoing` 里 **wall 在 tone 之前**；两条都各自 `makeInjectedMessage`，
  `source.kind = 'cardcatalog-wall'`，`form = 'wall'`。
- 去重：`state.wallCheckpoints: Map<sessionId, checkpointKey>` 加上
  `hasWallAfterCheckpoint(events, boundary)`。同一个压缩点只注入一次；
  出现新压缩点再注入一次。
- 压缩会把旧 wall 消息压掉 ⇒ 下一个压缩点自动重新注入。不需要持久化任何状态。

## 6. 日志

- 成功：`wall：压缩 3 次，最后 42 分钟前，注入一次`
- 无时间：`wall：压缩 3 次，注入一次`
- 无压缩点：`wall：没有压缩点，跳过`
- 关闭：不记。

## 7. 面板

新增 `wall` 卡片：开关 + `turns` + 只读状态行。

`statePayload()` 增加：

- `wallState ∈ 'injected' | 'no-checkpoint' | 'already' | 'disabled'`
- `wallCount`（压缩次数）
- `wallLastMinutes`（可能为 `null`）

状态行：

- `本会话压缩过 3 次，最后一次 42 分钟前`
- `本会话还没被压缩过`
- `压缩痕迹已注入过，等待下一次压缩`
- `已关闭`

文案里不出现用户的私人称呼、项目名、绝对路径。

## 8. 与 tone 的关系

| 注入 | 内容 | 频率 |
|---|---|---|
| 目录 | 账本**标题** | 每会话一次（走 system prompt） |
| tone | 压缩点之前的**原话** | 每个压缩点一次 |
| wall | 压缩的**元信息 + 命令** | 每个压缩点一次 |

wall 不含内容，tone 不含元信息；两者都不写文件。

## 9. 测试

新增 `test/v050.test.mjs`，7 个用例：

1. 没有 checkpoint ⇒ `no-checkpoint`，不注入。
2. 有 checkpoint + 之前有原话 ⇒ `ok`，含条数、`tone.cmd`、「不要说出去」。
3. `eventsBefore` / `userBefore` 数字正确（5 条事件、2 条真人消息）。
4. 已有 wall 在最后一个 checkpoint 之后 ⇒ 不重复注入。
5. 出现新的 checkpoint ⇒ 再注入一次。
6. `time` 缺失 ⇒ 没有「分钟前」，其余照写，`status === 'ok'`。
7. wall 与 tone 同时满足条件时，`outgoing` 顺序是 wall 在前、tone 在后。

同时修了一个测试自身的时钟依赖：nudge 用例先显式把 fixture mtime 设成“刚刚”，
避免检出时间变旧后“未过期”用例随机失败。

## 11. 代价

默认开启意味着**每个会话、每次压缩后**都会多一条 5 行左右的消息（约 150 token）。
如果重启时当前压缩点还没有留下 wall 消息，第一轮会补一次；已经有就不会重复。
不想要就在面板关掉；关掉后不再注入，也不清理已经注入过的。

## 12. 本版不做

- 不注入任何内容（不摘要、不列主题、不给片段）——那是 tone 和目录的活。
- 不统计跨会话，不做 token 估算，不新建任何存储。
- 不改目录 / nudge / tone 的现有行为（只增加一条独立消息）。
- 不写文件。
