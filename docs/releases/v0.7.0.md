# dsh-cardcatalog v0.7.0

第一次获得写权限：`upkeep` 在 markdown 源超过 `maxBytes` 时，把最旧的若干行搬进指定归档，
源文件只留文件头 + 一行指针 + 最新内容。**默认关闭，只对 `allowRewrite: true` 的源生效。**

## 1. 为什么

v0.6.0 落地了 `maxBytes` 红线，但只告警不动作。实测：

- `now.md` 涨到 4251 B / 4096 = 104%，越线；
- 手工把 14 条旧流水搬进归档，才回到 1511 B；
- 更糟的是中间那半天因为怕顶线而不敢记账——一个因为容量不够所以不敢写的账本，
  等于没有账本。

所以这一版必须让“到线就搬”变成机械动作。这是本插件第一次获得写权限，
所以规则要比功能多。

## 2. 配置

```yaml
upkeep:
  enabled: false
  keepPct: 60
```

- 只有 `upkeep` 这个对象标 `.extra('volatile', true)`，子字段不标。
- 默认 `false`；不开时与 v0.6 行为完全一致。

每个源：

```yaml
sources:
  - id: now
    kind: markdown
    path: ~/.dsh/notes/now.md
    maxBytes: 4096
    allowRewrite: true
    archivePath: ~/.dsh/notes/archive/now-{YYYY-MM}.md
```

- `allowRewrite` 默认 `false`；`archivePath` 为空 ⇒ 不写，日志
  `upkeep：<源> 缺 archivePath，跳过`。不猜默认路径。
- `DEFAULT_SOURCE` / `normalizeSource()` / 面板模板三处已同步。

## 3. 五步流程（`upkeep.mjs`，唯一允许写文件的模块）

1. **判定**：`stat(path)`；`maxBytes <= 0` 或 `bytes <= maxBytes` ⇒ `skipped`。
2. **快照**：复制整份源文件到 `$DSH_HOME/cardcatalog/backups/<basename>-<YYYYMMDD-HHmmss>.md`。
   失败 ⇒ `error`，源文件不动。
3. **算行**：从文件头之后的第一条 `- ` 开始，按整行搬，直到剩余 ≤
   `maxBytes * keepPct / 100`；至少搬 1 行。文件头（`#` / `>` / 空行）永不搬走。
4. **写归档（只 append）**：`{YYYY-MM}` 按本地月份展开；父目录不存在就创建；
   写完读回来逐行核对。
5. **核对 A/B/C**：
   - A：归档新增行 == 被搬走的行；
   - B：源剩余条目 == 原条目 - 被搬走；
   - C：源文件 size/mtime 与开始时一致。

   任一失败 ⇒ 回滚归档，源文件一个字节不动，返回 `error`。

最后：新内容 = 文件头 + 指针 + 剩余条目。写前删掉所有旧指针，只留一条新的；
先写 `<path>.upkeep-tmp`，`fsync`，再 `rename` 覆盖原文件。成功返回
`{status:'archived', moved, sizeBefore, sizeAfter, snapshot, archivePath}`。

指针格式：

```text
> 更早的 14 条已归档到 `notes/archive/now-2026-10.md`（2026-10-28 自动搬）
```

## 4. 触发

- 只在第一次 `agent/pre-step`（`step === 1`）跑；每天最多一次（内存 `lastUpkeepDay`）。
- 不在每轮 pre-step 里跑：写操作不进热路径。
- 成功日志：`upkeep：now.md 4251 → 1511 B，搬了 14 行到 notes/archive/now-2026-10.md`。
- 快照路径单独记日志。
- 任何失败只记日志，不抛到调用方，不影响宿主启动。

## 5. 面板

「维护」卡：

- `upkeep` 开关 + `keepPct`；
- 红字警告：**开启后本插件会改写你的文件；归档前会先做快照**；
- 显示快照目录；
- 每个源一行只读状态：`upkeepState ∈ 'off' | 'skipped' | 'archived' | 'error'`，
  `upkeepInfo: { at, moved, sizeBefore, sizeAfter, archivePath, reason }`。

## 6. CI：可审计白名单

`check:readonly` 改成三条：

1. 写 API（`writeFile*` / `appendFile*` / `rename*` / `copyFile*` / `unlink*` /
   `mkdir*` / `truncate*`）只允许出现在 `upkeep.mjs`；其他 `.js/.mjs`（含测试）出现即红。
2. `upkeep.mjs` 必须同时包含 `snapshot`、`verify`、`renameSync` 三个词。
3. 打印 `check:readonly: 0 处越界（白名单：upkeep.mjs）`。

测试里的临时目录改为“复制时排除文件/留给系统清理”，不再使用删除 API。

## 7. 测试

新增 `test/v070.test.mjs`，9 个用例：

1. 未超线 ⇒ `skipped`，内容与 mtime 都不变。
2. 超线 ⇒ `archived`；归档新增行 + 源剩余条目 == 原条目行。
3. 文件头不被搬走，位置仍在最前。
4. 指针对重：两次归档后只剩 1 行。
5. `allowRewrite: false` ⇒ 即使超线也零写入。
6. `allowRewrite: true` 但 `archivePath` 为空 ⇒ `skipped` + 日志。
7. 核对失败注入（归档少写一行）⇒ `error`，源文件一字节未变。
8. `{YYYY-MM}` 按当前本地月份展开。
9. pre-step 触发；归档后 `recent` 源仍能读到最新 3 行。

`makeCtx` 给了 `dshHomePath` stub；测试不碰真实账本。

## 9. 代价

- 每次触发会多一次完整文件复制（快照）；源文件很大时会有明显 IO。
- 每天最多跑一次；不做后台监听，不逐轮检查。
- 快照只增不减，需要用户自己清理旧快照。

## 10. 本版不做

- 不按天数/条目数归档（只按 `maxBytes`）。
- 不归档 `facts` / `jsonl`。
- 不重写归档内部的行（只 append）。
- 不做自动恢复 UI（快照只是文件，回滚由人 copy）。
- 不改 v0.6 的红线判据、不改目录 / nudge / tone / wall / decay 的行为。

## 11. 后续预留

`allowRewrite` 已经落地；后续若要扩展归档策略，必须继续满足：
默认关、白名单模块、快照先行、逐行核对、原子替换、失败源文件不动。
