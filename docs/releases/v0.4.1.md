# dsh-cardcatalog v0.4.1

修复 v0.4.0 的致命 schema 错误，并让 tone 在每个新压缩点后刷新一次样本。

## 1. 致命 schema 修复

v0.4.0 的 `tone` 对象标了 `volatile`，四个子字段又各标了一次。宿主的
`validateVolatileSchema` 不允许 volatile 嵌套 volatile，真实启动会直接拒绝整个
`Config`，连记忆目录一起不注入。

本版去掉 `tone.enabled` / `tone.turns` / `tone.maxChars` / `tone.header` 的子字段
`volatile`，只保留对象级标记。同时把源码注释改成：

> 只有对象级字段可标 volatile；子字段与 list 子项一律不标。

## 2. `check:schema`

新增 `ci/check-schema.mjs`，并接入 CI：

- 能解析到 `@deepseek-ai/schemastery` 时，构造一次 `Config` 并执行 volatile 放置校验；
- 解析不到时明确输出 `check:schema: skipped (schemastery not resolvable)`，不静默通过。

这样不再只依赖 `Config === undefined` 路径上的普通单测。

## 3. tone 去重改为按压缩点

v0.4.0 扫描全量事件，只要出现过一条 `cardcatalog-tone` 就永远不再注入。
本版按最后一个 `compact-checkpoint` 的 `seq`（没有 seq 时退回事件位置）作为去重键：

- 同一个压缩点只注入一次；
- 出现新压缩点后，允许再注入一次新的原话样本；
- 压缩点之前的旧 tone 消息不会挡住新压缩点。
